🎯 FUNCIONALIDADES PRINCIPALES
════════════════════════════════════════════════════════════════════════════════

1. BÚSQUEDA DE RESERVAS
   → Empleado accede a /panel/buscar-reserva-pago/
   → Busca cliente por nombre, DNI o email
   → Sistema filtra automáticamente:
     • Excluye vencidas (turno.fecha < hoy)
     • Excluye canceladas
     • Excluye ya pagadas (PAGADO)
     • Muestra solo PENDIENTE/SEÑADO

2. RESUMEN ANTES DE CONFIRMAR
   → Datos cliente: nombre, DNI, email
   → Datos turno: actividad, fecha, hora
   → Detalles pago: monto total / seña / SALDO RESTANTE
   → Campo bloqueado: monto a recibir (pre-llenado)
   → Checkbox obligatorio: confirmación de recepción
   → Botones: Confirmar / Cancelar

3. REGISTRO SEGURO DE PAGO
   → Transacción atómica (todo o nada)
   → select_for_update() bloquea reserva (previene 2 empleados)
   → Re-validación antes de procesar (TOCTOU protection)
   → Crea registro Pago con auditoría
   → Actualiza Reserva a PAGADO
   → Genera referencia única
   → Mensaje de éxito con detalles


✅ VALIDACIONES IMPLEMENTADAS
════════════════════════════════════════════════════════════════════════════════

Antes de permitir el pago, se valida:

✓ Usuario es EMPLOYEE (no cliente)
✓ Reserva EXISTE
✓ Reserva NO CANCELADA
✓ Reserva NO PAGADA (previene pago doble)
✓ Reserva en estado PENDIENTE o SEÑADO
✓ Turno NO VENCIDO (fecha >= hoy)
✓ Monto recibido >= adeudado
✓ Búsqueda sanitizada (sin SQL injection)

Cada validación genera error claro y descriptivo si falla.

❌ SOLUCIÓN DE PROBLEMAS
════════════════════════════════════════════════════════════════════════════════

Problema: No veo link "Registrar Pago en Sede"
Solución:
├─ ¿Estás logueado como employee?
├─ Ir a /admin/ y crear usuario con rol=EMPLOYEE
├─ Luego loguearse con ese usuario
└─ Volver a /panel/ (link debería aparecer)

Problema: Error 404 en /panel/buscar-reserva-pago/
Solución:
├─ Verificar que core/urls.py tiene:
│  path('panel/buscar-reserva-pago/', ...)
├─ Si no está, agregar la ruta
└─ Reiniciar servidor

Problema: Tests fallan
Solución:
├─ Ejecutar con verbose: python manage.py test ... -v 2
├─ Ver mensaje de error específico
├─ Verificar Actividad.Nombre.PADDLE existe
└─ Ver detalles en test output

Problema: Pago rechazado
Solución:
├─ Ver mensaje de error:
├─ Reserva vencida → Turno fecha pasada
├─ Ya pagada → Reserva.estado_pago == PAGADO
├─ Monto insuficiente → Monto < adeudado
└─ Turno cancelado → Reserva.estado == CANCELADA
